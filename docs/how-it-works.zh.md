# 一次评审是怎么跑完的

取舍论证见 [设计文档](design.zh.md)，配置见 [配置文档](configuration.zh.md)。

---

## 两趟：先逐文件，再看整体

一个改动文件 = 一个 agent，配只读工具。成本有上界，可断点续跑。代价是它看不见跨文件的问题——"这里改了，那边是不是也该改"，那个"那边"不在它的输入里。

让文件互相看见能解决，但会毁掉更值钱的一条：**中断后重跑，结果和没中断过一样**。它成立的前提正是每个文件只吃自己的 diff。

所以逐文件保持互不通气，跨文件另起一趟。

|  | 逐文件 | 整体 |
| --- | --- | --- |
| 谁决定看什么 | 程序 | 模型 |
| 轮次上限 | 6 | 14 |
| 输入 | 自己那个文件的 diff | 意图 + 各文件一句话说明 + 已报清单 |

---

## 流程

```
PR URL
  │
  ├─ ① 取材   REST 拉元信息 + unified diff + CI 诊断（不 clone）
  ├─ ② 脱敏   此后每个字符串都是 Redacted<string>
  ├─ ③ 切分   一个改动文件 = 一个单元；跳过锁文件/二进制/生成物
  │           文件数 > 1 时追加 #pull-request 单元
  │
  ├─ 逐单元、顺序、互不通气 ────────────────────────────
  │    ④ 规则扫描（本地 ¥0）  只看新增行，命中 → rule 证据
  │    ⑤ Agent 循环（≤6 轮）  get_file / search_diff / get_diff
  │                           ts_syntax_check / submit_findings
  │    ⑥ 定级                 rule|static → 可采纳；仅 llm → 参考
  │    ⑦ 落盘                 findings.jsonl → state.json（原子）
  │    ⑧ 重算预测             超支就降一档模型
  │  ──────────────────────────────────────────────────
  │
  ├─ ⑨ #pull-request（≤14 轮）
  │     输入：意图 + 文件清单 + 各文件说明 + 已报清单
  │           + 本次引入的名字（正则算出）
  │     工具：另加 list_changed_files
  │
  └─ ⑩ 全局去重 → 报告 / TUI 分诊 / 幂等回评
```

单文件 PR 不跑 ⑨。

**两处收口**：脱敏只在 ② 做一次，之后只接受 `Redacted<string>`，编译期强制；预算和 trace 挂在 pi 的 `streamFn` 上，每次 LLM 调用必经——新增一趟 agent 自动就有，不必为此写代码。

## 例一：一个被提交进来的密钥

`demo/src/config.ts` 新增 `awsAccessKeyId: "AKIAIOSFODNN7EXAMPLE"`。

**② 脱敏** 在任何东西看见它之前 → `[REDACTED:aws-access-key:1a5d]`。`1a5d` 是密钥 sha256 前 4 位：同一密钥处处同一标记，且不可逆。

**④ 规则** `secret-in-diff` 命中 → 天生「可直接采纳」，证据就是发现本身。

**⑤ 模型** 拿到规则命中作为上下文，并被告知别重复报。

**⑥ 定级，两道闸**：锚点必须落在 diff 触及的行（±3 行吸附），落不上就丢弃；引用的 tool call id 拿去 trace 核对，对不上就丢掉该引用（不是整条发现）。

| 证据 | 可直接采纳 |
| --- | --- |
| `rule` 正则命中 | ✅ |
| `static` 静态工具诊断 | ✅ |
| `llm` 模型推理 | ❌ |

不因"附近有规则命中"就提升档位：`console-log` 命中第 13 行，跟模型在第 13 行说的驱逐顺序无关。

### 「仅供参考」内部排序

模型自评 `◉确定` `◐多半` `○拿不准`，只决定组内排序（严重级优先），不改档位。

- 问法是"什么能证明你错"——"你有把握吗"的回答几乎总是"有"。
- 字段可选，漏填等同「拿不准」。必填的话漏一次 → schema 校验失败 → 那个文件的发现全丢。
- 「可直接采纳」不显示自评：在编译器诊断旁标"拿不准"，是在怀疑一个事实。

## 例二：一个没人调用的新函数

`retry.ts` 导出 `withRetry`；`session.ts` 的 `loadSession` 裸调 `db.query`。两个文件单独看都完整，逐文件那趟一条都报不出来。

这是整体那趟的第二类问题：**改了一半**——新加的东西没人用、新配置项没人读。只问"两处不一致"抓不到。

引入的名字由正则算出（`src/engine/introduced.ts`），不让模型推导：正则精确、免费、不花轮次；留给模型的是判断——**没有调用方是疏忽，还是不关这个 PR 的事**。

```
→ search_diff "\bwithRetry\b"    全 PR 只有定义，没有引用
→ get_diff session.ts            那 loadSession 呢
→ submit_findings
```

> **`withRetry` 在这次改动里没有任何调用方** · 次要 · 仅供参考 · 自评 **多半**
>
> `search_diff` 只找到这里的定义，没有任何新增或修改的代码使用它。如果它是给 `loadSession` 之类的调用准备的，这次提交少了接上去的那一步。

自评「多半」而非「确定」：PR 之外的代码可能在用它，而它看不到。

定级查的是**发现所指文件**的 hunks——沿用逐文件那套（只认本单元的行）会把这趟报的每一条都否掉。

## 断点续跑

```
runId = sha256("github:yanmxa/code-review:1:b5afa3ff…").slice(0, 12)
          ↑平台      ↑仓库              ↑PR号 ↑head SHA
```

同一 PR、同一 head commit → 必然同一目录，用户不用记 id；有新提交就是另一次运行。

| 启动时 | 动作 |
| --- | --- |
| 目录不存在 | 全新运行 |
| diffHash 对得上 | 续跑 |
| diffHash 对不上 | PR 被改过 → 丢弃重来并告知 |

中断的单元重置为待办，**但账不抹**——token 是真花掉了。

写入顺序：**先 `findings.jsonl` 追加，后 `state.json` 原子替换**。崩在中间只是重跑一个单元；反过来会永久丢掉一条已付费的发现。代价是 jsonl 会有重复，所有拿给人看的地方都先 `dedupe()`。

## trace 与否决记忆

每条发现关联一个 trace（`traces/<unit>.jsonl`）：完整 prompt、模型原始回复、每次工具调用与结果、逐次用量。看法：报告里的路径、TUI 按 `t`、或 `code-review trace <run> <unit>`。

发出的评论带 `<!-- code-review:f:<fingerprint> -->`。下次运行比对 PR 上还剩什么——**删除**或线程 **resolved** 记为否决，永久不再报；回复反驳算讨论不算判决。记忆是仓库级的（运行目录按 head SHA 建，放那儿会在下次 push 时蒸发）。

## 成本分布

一次真实运行（4 个文件）：

| 阶段 | 成本 |
| --- | --- |
| ①②③④ 取材/脱敏/切分/规则 | ¥0 |
| ⑤ 逐文件 Agent | 约 ¥0.14 |
| ⑨ 整体那一趟 | 约 ¥0.02，不随文件数线性增长 |
| ⑥⑦⑧⑩ | ¥0 |

④ 零成本又恰好产出最高价值的那几条，所以**预算耗尽后照跑**。实测 `--budget "9k tokens"` 时 4 个文件只有 2 个过了 LLM，报告里仍有 8 条可直接采纳。

## 已知的机制缺口

- **规则只看新增行**——删掉一个鉴权检查、拿掉一个校验，零条规则命中。
- **`no-test-change` 是 PR 级事实却按文件报**，改 20 个文件刷 20 条；且它是启发式不是缺陷，却在「可直接采纳」档里。
- **锚点必须落在改动行**，而最值钱的发现是"本该改而没改"。上面那条 `withRetry` 锚在定义处，而非最该被看到的 `session.ts:15`。
- **去重靠标题文本**（path + 归一化标题 + 行号/5），同一问题换个说法就是两条。
- **没有仓库级搜索**——`search_diff` 只搜改动过的行，所以"PR 之外有没有人用它"问不出来，那条发现因此只能是「多半」。
- **整体那趟排在最后**，降级链降到底才轮到它。
